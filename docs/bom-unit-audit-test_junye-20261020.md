## 唯一阻断项

- 产品：`11080011`，散装结构胶 红色，产品 ID `39`。
- 清单 ID `26`，版本 ID `26`，`V1`，标准总量 `1`。
- `UnitConversionId=345`，但该关系属于产品 `38`，比例 `201.3`。
- 产品 `39` 自己的关系为 `346`，`1 釜 = 201.7 kg`。
- 版本 `UnitInfo` 仅有 `Id=-1 / kg / Ratio=1`，没有所选单位 `345`。
- 因此用 kg 或釜派工，均无法找到该版本默认清单单位，1、10、100 三种派工量共 6 个失败场景。

修复建议：在物料清单 V1 重新选择正确的产出单位并保存完整单位快照。如果该清单表示一釜产出，应使用本产品换算 `346`，同时保存 kg 与釜的对应关系。需先确认清单确实以一釜为底数；不能只换 ID，也不能在未确认底数时改成 kg。此次未执行数据修复。

## 检查方法与边界

通过只读事务取得数据库配置，按照当前 Controller 重建产品、规格、包装单位列表以及 BOM/配方首层和替料数据，然后直接执行现有 Vue 页面的 `prepareRowUnits`、`resolveBomConversion`、`getBomQuantity` 方法。规格次单位使用类型20，规格到产品关系使用类型12，产品次单位使用类型10，包装按接口现有连接规则处理。产出换算优先使用版本中完整关系，必要时使用最新单位中的完整关系，没有混用两个来源的比例。

这验证的是所取数据和当前源码的单位匹配、换算可解析性，不是宿主 HTTP/界面端到端联调，也不能代替人工确认实际包装容量或配方耗用是否正确。
